## Delivery order and dependencies

M0 comes first because the existing Python VisionIPC fixture cannot register external DMA-BUFs, and the current rotation fixtures do not isolate production paths. The C++ helper must register external `VisionBuf` objects through `VisionIpcServer::register_external_buffers`, use four system DMA-heap buffers per configured stream at the test geometry, bracket CPU writes with `DMA_BUF_IOCTL_SYNC`, and call `send(..., sync=false)` so the ION-specific generic sync method is not called. It owns mappings and fds until VisionIPC and both processes have stopped.

M1 and M2 can be implemented in parallel after M0's contracts are executable. The new timer, per-output watchdog/recovery, runtime writer finalization, `LoggerdRotationReport`, queue handling, and audio buffering apply only when the deterministic KA2 protocol is active: RK3588 with `ENCODERD_DETERMINISTIC_DISABLE` unset or zero, and, for loggerd tests, `LOGGERD_TEST_DETERMINISTIC=1`. Non-KA2 runs and RK3588 with `ENCODERD_DETERMINISTIC_DISABLE=1` keep their pre-r8 behavior. Do not put the new commit hook in the shared startup `logger_rotate()` helper; initial startup must remain writer-free and must not emit a rotation report. M1 makes actual packet output—not `encode_frame()` submission—the per-output heartbeat, uses fair rounds under one 900 ms EOS drain deadline, and prevents local failure or drain timeout from stopping encoderd or triggering failure-recovery reopen/retry of a healthy sibling. An ordinary segment boundary still performs its already-planned close/open once per healthy output. M2 adds its timer and exact commit behavior only to that protocol. M3 starts only after both are complete so integration exercises the final protocol rather than a temporary mixed version.

Before **each** KA2 test run, check active camera/loggerd/encoderd/video-device/MPP users and stop if competing device work is present. The inherited host snapshot had no camera, loggerd, encoderd, or video-device users, while manager, uploader, and deleter processes were active; recheck rather than assuming that snapshot still holds. Do not stop those unrelated processes. Set unique temporary `LOG_ROOT`, `PARAMS_ROOT`, and `OPENPILOT_PREFIX` before any test constructs `Params` or starts loggerd/encoderd. Set `LOGGERD_TEST_DETERMINISTIC=1` for tests of the deterministic KA2 protocol; keep `ENCODERD_DETERMINISTIC_DISABLE` unset or zero except in AC-12's explicit legacy case. Seed only isolated `RecordFront` and `RecordAudio` values. Start loggerd, encoderd, and the test publisher directly under those roots; never attach to the live camera/V4L2 publisher or write production route/Params paths. Always stop child processes and close/unmap fixture resources in `finally`. Qualification is synthetic DMA-heap only: the live V4L2 exporter, its DMA-BUF fence behavior, and live buffer reuse remain unqualified; this plan authorizes no live-camera claim or run.

## Rollout and rollback shape

| Stage | Audience | Mechanism | Rollback | Trigger to advance |
|---|---|---|---|---|
| Implementation and host validation | Build/test owner only | Isolated worktree/build; no manager service or production paths; unit/fault tests first | Revert the unaccepted code changes; do not add a copy mode or runtime selector | Unit tests pass and all D-28/no-copy invariants hold |
| KA2 synthetic lifecycle qualification | Named runtime/test owners | Direct loggerd+encoderd under isolated temp roots with DMA-heap fixture and explicit fault arms | Stop and clean the isolated processes; keep the candidate unpromoted if any acceptance fails | AC-1 through AC-12 pass; qRoad and each healthy track pass their full-path checks; legacy modes and startup remain unchanged |
| Merge/release consideration | Project owner/reviewer | Separate code/security review and explicit release decision; this plan authorizes no deploy | Keep the candidate out of the release. If later rollout fails, use a previously approved image only if its behavior is known safe; otherwise stop rollout and escalate instead of re-enabling full-resolution copying or reverting to an unbounded-stall build | Review-to-delivery and any requested release approval close all blockers |

There is no zero-copy switch, copy fallback, or new kill switch in this design. Release is held until the valid DMA-BUF path and degraded failure path both meet their acceptance contracts. D-29's failure arm intentionally permits the rejected full-resolution stream's frames, pending frames, and—after bounded audio expiry when no qRoad writer exists—audio samples to be dropped with explicit counters. This does **not** relax the healthy DMA-BUF arm: D-16 still requires every submitted frame exactly once for every healthy stream over the whole process lifetime, including startup and teardown; qRoad may not be omitted by the selected deadline.

## Build handoff

The implementation spec should refine ownership and code/test touchpoints without moving these boundaries: no full-resolution fallback; 5 s timer independent of service messages; per-epoch readiness; packet-progress-based per-output health; fair 900 ms EOS drain; continue the segment advance after a local drain timeout; close/quarantine only timed-out outputs; give every healthy output exactly one planned close/open per ordinary boundary; and keep failure-recovery reopen/retry counters per output. qRoad must remain healthy and emit post-boundary packets without sibling-triggered recovery. Also preserve commit-time writer closure, segment-checked video/audio queues, and separate invalid-input, silent-output, and drain-timeout acceptance paths. Any necessary boundary change returns to architect rather than being hidden in implementation detail.
